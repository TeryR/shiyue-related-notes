## 第一次使用：三步走

**第 1 步：安装插件**（见 README「安装」一节）

**第 2 步：配置模型**（设置 → 智能关联）
- 用 Ollama：切到「Ollama 本地模型」，确保已 `ollama pull bge-m3`，点「测试连接」
- 用 OpenAI 兼容接口：填 API 地址、API Key、模型名，点「测试连接」

**第 3 步：建立索引**
- 配置完成后插件会自动开始后台索引，状态栏右下角显示「智能关联：正在索引 123/1200…」
- 也可以手动：设置 → 索引管理 → 「立即重建索引」
- 索引跑完，状态栏显示「智能关联：已索引 1200 篇」

> 提示：第一次索引 1000 篇笔记，Ollama 本地大约需要几分钟（取决于电脑性能）；在线接口通常 1-3 分钟。索引期间不影响你正常记笔记，全部在后台进行。

## 侧边栏智能推荐

这是最核心的功能：**打开哪篇笔记，右边就列出与它语义最接近的笔记**。

打开方式（任选）：
- 点击左侧边栏的 ✨ 图标
- 命令面板（Ctrl+P）→「打开智能关联面板」
- 点击状态栏的「智能关联：已索引 X 篇」

每个推荐条目显示：
- 笔记标题 + 相似度百分比
- 内容摘要（前 200 字）
- 鼠标悬停出现 ＋/－ 调优按钮（见「调优反馈」）

点击任意条目即可跳转到那篇笔记。如果觉得推荐太少/太多，到设置里调「最低相似度」（默认 0.4，调低→更多推荐）和「推荐数量」（默认 5）。

## 嵌入模型变更后怎么办

- 换模型后：旧索引**保留且继续可用**（推荐不会突然消失），状态栏与设置会提示「模型已变更，待重建」
- 想用新模型重建时：点「继续索引」→ 弹确认框 → 清空旧索引并用新模型重算（可随时停止，已完成部分保留）
- 不点就不会重建，随时可以切回旧模型（旧索引还在，直接可用）

## 语义搜索

不用记关键词，用大白话搜笔记。

1. 命令面板 →「语义搜索」（或直接 Ctrl+P 输入「语义搜索」回车）
2. 输入描述，比如：
   - 「减脂期怎么吃蛋白质」
   - 「汉武帝和匈奴打仗的事」
   - 「孩子写作业拖沓怎么办」
3. 结果实时出现，按相关度排序，带百分比和**命中片段摘要**（v1.2 混合检索：向量 + 关键词双路融合）
4. 点击结果打开笔记；回车打开第一条

**v1.2 检索原理（分块 + 混合检索）**：
- 长笔记先切成语义块（按段落/标题边界 + 句边界 + 重叠），每块独立向量——长笔记的局部内容也能被搜到
- 搜索时同时跑两路：向量路（按意思匹配）+ 关键词路（BM25，精确术语如人名/代码/型号），加权融合排序
- 结果显示命中的块片段，比整篇摘要更精准

语义搜索和普通搜索的区别：普通搜索是字面匹配（搜「狗」找不到「宠物」），语义搜索按意思匹配（「宠物」相关笔记也能找到）。

## Smart View：笔记内嵌相似笔记

把相似笔记列表嵌进当前笔记里，随时对照。在笔记中插入：

````markdown
```smart-connections
minSimilarity: 0.4
maxResults: 10
maxCharacters: 500
```
````

- `minSimilarity`：最低相似度（0~1，默认 0.4）
- `maxResults`：显示条数（1~100，默认 10）
- `maxCharacters`：摘要字数（默认 500，写 0 不显示摘要）

三个参数都可省略。列表会跟随当前打开的笔记实时刷新。**语法与原版 Smart Connections 完全一致**，原版笔记里的代码块直接可用。

## 智能对话

基于你的笔记回答问题的 AI 助手。

1. 命令面板 →「智能对话（基于笔记）」
2. 提问，比如「帮我总结一下我关于投资的笔记里都写了哪些原则？」
3. 插件会先检索与问题相关的笔记，把内容作为参考喂给 AI，然后流式回答
4. 顶部徽标显示「参考了 N 篇笔记」——回答有据可查
5. 右侧「保存对话」把本次对话存成一篇笔记（`智能对话-日期-时间.md`）

注意事项：
- 对话模型和嵌入模型是分开配置的（设置里各有各的模型名）
- 对话只在本会话内保持上下文，「新对话」按钮清空

## 改写选中文本

1. 在编辑器中选中一段文字
2. 命令面板 →「改写选中文本」
3. 等 AI 改写完成，点「替换原文」直接替换，「复制」拿走，或「关闭」

适合润色周报、改病句、让表达更顺。

## 从选中内容生成笔记

1. 选中一段素材（网页摘抄、会议记录、灵感碎片）
2. 命令面板 →「从选中内容生成笔记」
3. AI 会生成一篇带标题、分小节的 Markdown 笔记
4. 点「保存为笔记」→ 自动存为 `标题.md` 并打开；重名自动加序号

不选中任何文字时，自动使用当前整篇笔记作为素材。

## 索引状态与维护

索引进度有 **4 个可见位置**：

| 位置 | 显示内容 | 时机 |
|------|---------|------|
| 侧边栏面板顶部 | 进度条 + 「正在索引 123/1209（10%）· 当前笔记名」 | 索引进行中（最显眼） |
| 状态栏（右下角） | 「正在索引 123/1209…」/「已索引 1209 篇」 | 常驻，点击可打开面板 |
| 通知弹窗 | 「开始索引 N 篇…」「索引完成，共 N 篇」 | 首次/重建等全量索引时 |
| 设置 → 索引管理 | 实时进度条 + 已索引/总数、模型、更新时间 | 设置页打开期间实时刷新 |

三个管理入口都能看索引状态：
- **状态栏**：实时显示进度/数量；索引出错时变红显示「索引出错」
- **设置 → 索引管理**：已索引/总数、嵌入模型、最后更新时间 + 实时进度条
- **命令面板 →「查看索引状态」**：弹窗显示同样信息 + 「立即重建索引」「清空索引」按钮

什么时候用哪个操作？——**这是最容易混淆的地方，记住一条规则**：

| 操作 | 做什么 | 什么时候用 | 耗时 |
|------|--------|-----------|------|
| **继续索引（增量补齐）** | 只嵌入未索引或内容已修改的笔记，已索引的直接跳过 | 日常补跑；索引中断/出错后接着跑；大量导入新笔记后 | 快（通常几秒~几十秒） |
| **重建全部索引（清空重算）** | 清空全部向量重新计算 | 只有两种情况：换了嵌入模型、索引损坏或结果明显不对 | 慢（全量重来） |

**索引自动重试机制**（无需手动干预）：
- 瞬时错误（网络波动、超时、限流 429、服务端 5xx）：自动退避重试（次数可在设置 → 高级 →「嵌入请求重试次数」调整，默认 3）
- 内容超长：自动降级截断后重试（4000→2000→1000→500 字符），不影响其他笔记
- 配置类错误（API Key 无效、模型不存在）：不盲目重试，直接中文提示去设置修复
- 完成通知会显示「本次嵌入 N 篇，自动重试 M 次」

**编辑中的笔记什么时候被索引？**
- 你打字时插件不会频繁打扰：修改事件合并后（约 1.5 秒）才入队，且 v2 分块索引只重算变化的那几个块
- 每隔 10 分钟还有一次静默兑底扫描，任何遗漏（比如编辑器尚未写盘的边缘情况）都会被自动补齐
- 所以：写完一段等几秒，或者随手点一下「继续索引」，推荐就会更新

- 自动增量（改笔记后自动跑）和「继续索引」是同一件事，都是跳过未变化的笔记
- 「重建全部索引」永远带确认弹窗，误点也不会直接执行
- 索引出错时，状态栏点击弹出的窗口里两个按钮都有——**先点「继续索引」**，配置没问题的话它会把剩下的跑完；修好配置后也用它

什么情况下需要重建？
- 换了嵌入模型（切换模型后插件会自动重建）
- 索引文件损坏或结果明显不对
- 大量导入笔记后想重新整理

**清空索引只删缓存，不动笔记**，随时可以重建。

## 调优反馈

侧边栏推荐条目悬停会出现两个小按钮：
- **＋**：这类笔记更相关——以后推荐会向这类笔记倾斜（点击后会弹确认框，防误触）
- **－**：这类笔记不相关——推荐会避开（点击后会弹确认框，防误触）

头部会显示「已调优 N」，点击徽标可清除全部调优（设置 → 索引管理里也能清除）。调优**持久化保存**，重启 Obsidian 后依然生效；它只调整推荐排序（微调查询向量），不影响索引与向量缓存，随时可清。

## 从英文原版迁移过来

1. 先确认原版使用的嵌入模型（原版设置里能看到），在中文版设置里选同一个模型（或直接用 bge-m3，中文效果更好）
2. 安装并配置好中文版，等待索引完成
3. 确认中文版一切正常后，再禁用原版
4. 原版的 `embeddings.json` 数据文件格式不同，**不能直接复制**；迁移旧索引 = 重新索引一遍（几分钟而已）
5. 笔记里的 `smart-connections` 代码块无需改动，中文版语法兼容

> ⚠️ 两个插件同时启用会各自建一份索引，占用双倍磁盘，建议迁移期结束后禁用其中一个。
